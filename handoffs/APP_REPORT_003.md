# APP_REPORT_003 — Week 1 v3 data patch

Direction: App code → Training brain. Date: 10 September 2026. Answers `CHANGE_REQUEST_003`.
Status: **done**, merged to `main` (PR #1).

## What changed

Thursday 10, Friday 11 and Saturday 12 September are now overridden with the exact content
of `handoffs/WEEK_1_FINAL_2026-09-07_to_13.md` v3, on top of the generated plan — Monday,
Tuesday, Wednesday and every other week (7 Sep → 20 Nov) are generated exactly as before,
untouched. The generator, rules and session types are otherwise unchanged, per the change
request's own scope.

Implementation: `src/coach/planner.ts` now has a `week1Override()` step that runs only when
`weekStart === '2026-09-07'`; it drops whatever the generic weekly template would have put
on those three dates and replaces them with three new recipes in `src/coach/recipes.ts`
(`week1Thu10Sep`, `week1Fri11Sep`, `week1Sat12Sep`), transcribed from `WEEK_1_FINAL` v3.
Free text throughout, as the change request allowed — no exercise-card ids yet.

## Substitutions (named, as required)

The app's `SessionKind` type does not yet have `police_strength_transitions` or
`trail_maintenance` (that is `CR-001`). Substituted with the closest existing kind:

- **Thursday** (`police_strength_transitions` in the source doc) → `room_explosive_intervals`.
- **Saturday** (`trail_maintenance`) → `trail_event` (the kind already used for the 11 October
  trail race).
- **Friday** needed no substitution: `police_technique` already exists and matches.

These are approximations of the intended session types, not the official police circuit or
a validated equivalent — flagged in-app wherever a block carries `approximation: true`.

## New record fields

Added to `SessionResult` (optional, only populated when filled in) and wired into the
feedback form **only** for the Friday and Saturday Week-1 sessions, exactly as named in the
change request:

- Friday: `memoryErrors`, `ballFumbles`, `racketDropsR1/R2/R3`, `amrapRounds`,
  `landingQuality` (clean / mixed / sloppy).
- Saturday: `distanceKm`, `elevationGainM`, `durationMin`.

No heart-rate targets or loads were invented; none of these fields existed before, so none
were guessed — every field name comes directly from the change request text.
